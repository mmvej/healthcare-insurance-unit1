Unit 1: Data Analytics and Python for Data Preparation.

This project explores recorded medical insurance charges in the Healthcare Insurance dataset. It includes the executed assessment notebook, source and cleaned data, and a Streamlit dashboard. Explanations use plain language and the notebook labels Tasks 1-4 and criteria 1.1-4.2.

## Questions and findings

The three questions compare charges by smoking status, examine age/BMI associations, and compare regions before and after separating smoking groups.

The downloaded file contains 1,338 rows and seven fields. Mean charges are 13,270.42 and median charges are 9,382.03. Mean charges are 32,050.23 for smoking=yes (274 records) and 8,434.27 for smoking=no (1,064 records). The notebook reports distributions, within-group correlations and regional comparisons, including group sizes.

These are associations within the sample. The currency, observation period, sampling coverage and exact region boundaries are not confirmed by the retrieved source. The data cannot support current financial forecasts, treatment-effect claims or individual pricing decisions. Recorded charges are not assumed to be premiums.

## Optional predictive regression

The notebook and dashboard include a linear regression with a BMI–smoking interaction, using all six source predictors. A fixed grouped split retains 1,070 training rows and 268 test rows, keeping exact duplicates together. Encoding and fitting use training data only; the comparison predicts the training median. The test MAE is 2,723.40 versus 7,721.87 for the baseline (64.7% lower). MAE is measured in the original charge units, not as an accuracy percentage. Test MAE is 2,477.32 among non-smokers and 3,942.85 among smokers.

This is exploratory held-out prediction within the supplied sample. The interaction was motivated by prior full-sample exploration; the single split is not independent external validation. It is not a current-cost forecast or an individual pricing tool. The dashboard report uses the fixed full-dataset split regardless of the descriptive filters. See `src/regression.py` for the reproducible method.

## Run the project

The tested local environment uses Python 3.14. Requirements pin the installed direct dependencies. Use Python 3.14 on a deployment service that supports it, or validate compatible package versions in the service's supported Python environment before deployment.

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python -m jupyter notebook notebooks/healthcare_insurance_analysis.ipynb
```

If the notebook command is unavailable, install the optional notebook interface with `python -m pip install notebook`, or open the ipynb in VS Code/JupyterLab using the virtual environment. ```bash

```bash
python -m pytest -q
ruff check src app.py tests scripts
```

The cleaned CSV is included. To regenerate it, run the notebook, which preserves the raw file, prepares the data, validates it, saves it and checks the reload. No API key is required. ## Data source and handling

[Healthcare Insurance, willian oliveira, Kaggle](https://www.kaggle.com/datasets/willianoliveiragibin/healthcare-insurance), version 1, accessed 27 October 2026. Downloaded through Kaggle's public endpoint. Metadata lists CC0: Public Domain. See `evidence/source.md` and `evidence/kaggle_metadata.json` for the recorded description, permissions and limitations. The 2023 upload date is not assumed to be the medical observation date.

The source has no missing values. The one repeated row is retained because there is no identifier proving an accidental duplicate. High charges are retained. Readable categories remain intact; age bands have explicit boundaries. The raw data is separate from derived outputs and its hash is checked. No credentials or confidential health records belong in the repository.

CSV is sufficient for this static sample; a controlled database would be preferable for growing, linked operational claims. The notebook assesses completeness, consistency, validity, uniqueness, accuracy and timeliness and explains which cannot be verified. It also discusses privacy, security, CC0, bias and the conditional relevance of UK health-data guidance and HL7 FHIR.
